# 140 — Moving Simple Steps onto core 1.0.3

> Written 2026-11-17, for core **`v1.0.3`** (commit `adfaf87`, branch
> `core-handover`, after the pinned 1.0.2 `dbaf4c7`); every core property test
> passed at 2,000 examples on its code. Core's guide to this
> move, with every change and its tests, is
> [app-update-1.0.3.md](../../external/simple-steps-core/docs/design/app-update-1.0.3.md);
> this page is the app's side of it. Earlier moves: [core_migration.md](core_migration.md)
> (1.0.1, 1.0.2).

**Goal.** Take 1.0.3's fixes with the smallest change that keeps today's
functionality, drop the three shims it closes, and replace the app's own
session saving with core's. New features (stages, bulky cells on disk) are §3,
each its own decision.

## 1. What changes, and what the app adjusts

| # | Core change | Where the app meets it | Adjustment |
|---|---|---|---|
| 1 | **Run brings steps up to date**: `k.run(name)` leaves a current step (completed, or failed with nothing changed) as it is; `force=True` runs it again; a source tool runs again whenever run by name | `kernels.py:502`, *Run step* | keep `s.k.run(name)` for **Run**; add **Run again / Retry** as `s.k.run(name, force=True)`. Tests that click Run twice and expect a second call change |
| 2 | **A column argument under `collapse` gets each group's values** (it got the whole column, a silent wrong answer) | workflows binding a column explicitly under `collapse` | results change, rightly; update any expectation that pinned the wrong value |
| 3 | **Steps go stale where they should**: a binding core wrote by type (`slow=wf["a"]["a"]`), a change inside a big image or array | the grid's out-of-date marks | none: more `stale` where it is due |
| 4 | **Image and figure data versions are their content** | image and figure columns | a reopened or running workflow may show their readers `stale` once |
| 5 | **A load checks results as they are now**: a changed tool shows `stale`, *tool changed* (it showed `completed`), also through the session export | `core_bridge.restore_with_outputs` | none; replaced in #8 |
| 6 | **A DataFrame step from a light `to_json` loads `invalid`** (`data_missing`), never raising at run; a data step's spec has `"data": {"in": …}` | `file_manager.py`, if it saves `k.to_json()` for data steps | save with `k.save` (#8); show the code `data_missing` |
| 7 | **`k.view` / `k.cell` don't crash on arrays** (C37) | `core_bridge._patch_plain` | **delete the C37 shim** |
| 8 | **`k.save(folder, outputs=True)` / `Kernel.load(folder, catalog)`**: a session folder, `workflow.json` + `data/<step>/{table.parquet, states.parquet, meta.json, files/}`, exact or reported (`report.json`), reopening with nothing to run | `core_bridge.save_with_outputs` / `restore_with_outputs` (C32), and where `file_manager.py` puts a workflow away and opens it | **delete the C32 shim**: put a kernel away with `k.save(folder, outputs=True)` into a folder per workflow; open with `Kernel.load(folder, catalog)`; show the report when `exact` is false |
| 9 | `describe()`'s `name=` default (fixed in 1.0.2) | `core_bridge` C36 | ~~delete the C36 shim~~ **keep it**: run 2026-11-17 on 1.0.3, `describe()` still lists `name` for six verbs and core refuses it (008 C36) |
| 10 | **pyarrow** is a dependency of core | the app's environment has no pyarrow (checked 2026-11-17) | reinstall after moving the pin; `smoke_install.py` sees it |

Shims left after this: C18, C33, C34, C36, C45 (core's P1).

## 2. Gates

`pytest` at baseline, `examples/runme.py`, `cd frontend && npx vitest run`,
`python scripts/preflight.py --fix`, `python scripts/smoke_install.py`, and the
UI end to end: declare, run, edit (stale), **save, close the workflow, reopen it
with every result shown and nothing to run**, Run again on one step.

## 3. Later, each its own decision

| | What core makes possible | Needs in the app |
|---|---|---|
| L1 | **Stages**: `k.stage(name, first=, last=)`, `k.run_stage(name)`, **`k.stage_status(name)`** (one state, what needs a run, the step it ends with), `k.rename_stage`, `k.unstage`, `k.stages` | a stage folded as one block in the step strip, its state from `stage_status`; *Run stage*; read `k.stages` after each edit (no `on_change` for stages yet) |
| L2 | **Bulky cells on disk** (opt-in): `Kernel(catalog, spill_over=n, store=folder)`; cells hold a `MediaHandle` (`.summary`, `.kind`, `.load()`); `k.value(step, row, column)` | `cell_types.py` renders a handle from `.summary` (no pixels); `/api/cell` loads with `k.value(…)`; `store` = the workflow's session folder, so a save copies nothing; `Kernel.load(…, spill_over=n)` to reopen big sessions without loading every image |
| L3 | **Run again** | a *Run again* control on a step, a stage and *Run all* (`force=True`) |

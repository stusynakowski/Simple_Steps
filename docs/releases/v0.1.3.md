# Simple Steps 0.1.3

On `simple-steps-core` 1.0.2 (`dbaf4c7`), as 0.1.2.

```bash
pip install "git+https://github.com/stusynakowski/Simple_Steps.git@v0.1.3"
```

## The Formula panel shows how the formula maps to its fields

Press **fx**: the step widens, and the formula is shown in parts across the
top, with a dotted line from each part (the tool, each modifier, what it
runs over, each argument) to the field that edits it. Hover either end and
both light up.

- **Runs over** is the first argument: the step the tool is applied to.
  Its note says how its columns fill the parameters you don't set, by name.
- Under each argument that reads a step, the panel says **what the tool
  receives**: each row's own value, one value, a list, or a table. Never the
  `#` column or a column's name. An argument can read a column of any name:
  `n=wf["r"]["score"]`.
- A step that's just a value (`=[1, 2, 3]`) or a copy (`=wf["r"]`) says
  **No tool**, with its value or step as the field.
- Drag the divider between the tool and the arguments; the lines follow.

## The step header

- The name and status are on **one line**.
- The step's **settings** and **notes** are in the header, beside the name,
  on hover (they've left the toolbar).
- Notes open from a small arrow at the header's bottom left, on hover, as
  a description under the header in the step's colour. Folded, nothing
  shows.
- The status is readable on any step colour.

## Run status on the steps map

The map along the bottom shows where a run stands: a thin line over each
step, **grey** staged, **blue** queued or running, **green** ran,
**orange** some rows failed, **red** failed. Hover it for the status; click
to jump to the step.

## Fixed

- The steps no longer **jump sideways** when you choose a tool from the
  formula bar's list or pick a cell while writing a formula; the cursor
  stays in the bar. The tool list also opens on an empty bar.
- A selection core refuses (`wf["s"][1][2]`) shows core's message, instead
  of an error that also stopped the whole workflow from syncing.
- `=wf["r"]` on its own runs as a copy of the step.
- Reference boxes in the grid: `[-1]`, `[-2:]` and `cols[1]` are boxed
  where core reads them; a condition is no longer boxed as the whole table.
- The formula bar's placeholder no longer shows the retired syntax.
- The in-app docs match the app and core 1.0.2 (`mod.name(…)`, not
  `name=` in a verb; the new toolbar; any model for the agent).

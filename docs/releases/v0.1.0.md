# Simple Steps 0.1.0

The first tagged release, on `simple-steps-core` 1.0.1 (`fed4d1a`).

```bash
pip install "git+https://github.com/stusynakowski/Simple_Steps.git@v0.1.0"
simple-steps --load-examples
simple-steps run examples/app.py
```

## What reads differently on core 1.0.1

- **A step's one output column takes the step's name.** `dbl` gives a column
  `dbl`, where it used to give `value`. Source steps, literals and the empty
  step still give `value`; core has been asked to make that one rule.
- **A verb you don't write is decided and written into the step**:
  `mod.map()`, with a default breaker. A tool returning `True`/`False` with no
  verb gives a column of them; to keep rows, write `mod.filter()`.
- **A parameter takes the one column of its type**, and core writes the
  binding into the formula (`name=wf["people"][cols["first"]]`). With two
  candidate columns it's refused, and the message writes the fix.
- **Only the edited step goes stale.** A step reading it is marked out of date
  until it re-runs, and turns stale itself once its input re-runs with new
  data.
- A tuple widens to `var0, var1` (was `c0, c1`).

## New in the UI

- A step's **problems** (why it can't run) are listed in its summary and on
  its status pill's hover.
- A step reading a stale one shows **out of date**, with core's reason
  (`read stale 'nums'`).
- **Core runs:** in the summary shows the formula core runs when it differs
  from the one written: the verb it decided, the bindings it wrote.

## Fixed

- **Security:** the Explorer's file routes kept paths inside the workspace by
  comparing strings, so a sibling folder (`../ws2` beside `ws`) and symlinks
  leading out could be read and written. Paths are now resolved and compared
  by folder (spec 015).
- The grid's view of a step (`/api/view`) failed on every step on core 1.0.1.
- A formula run outside a workflow named its column `__formula__`.

## Not yet

- Progress and cancelling a run, re-running only failed rows, stages, saved
  outputs that survive a restart, and media handles wait on core.
- The formula bar still uses the app's own parser; moving to core's
  `formula()` is the next piece of work (`docs/dev_plan/core_migration.md` §6).
